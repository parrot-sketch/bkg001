# Event Catalog — Tiered for Phased Rollout

**Purpose:** Complete inventory of all domain events, classified by implementation priority. Use this to plan phased rollout of event infrastructure.

**Event Naming Convention:**
- Pattern: `domain.action.object`
- Tense: Past tense, descriptive, immutable
- Examples: `intake.session.created`, `patient.record.confirmed`

---

## Event Categories

| Category | Purpose | Examples |
|----------|---------|---------|
| **Lifecycle Events** | Entity creation, updates, and deletion | `patient.created`, `appointment.updated` |
| **Workflow Events** | State transitions in business processes | `intake.confirmed`, `queue.assigned` |
| **User Events** | Authentication and user actions | `user.logged_in`, `doctor.logged_in` |
| **Clinical Events** | Medical/clinical workflow milestones | `consultation.completed`, `vital_signs.recorded` |
| **Financial Events** | Billing and payment milestones | `payment.received`, `invoice.created` |
| **Notification Events** | Communication dispatched | `reminder.sent`, `notification.delivered` |
| **AI Events** | Agent detections and suggestions | `duplicate.detected`, `anomaly.flagged` |
| **Audit Events** | Compliance and security logging | `audit.recorded`, `consent.signed` |

## Open Questions

1. **Event Retention:** How long should events be retained? 7 years for compliance? Indefinite for analytics?
2. **Event Replay:** Should the system support replaying events to rebuild state? This determines if events are append-only forever.
3. **Event Versioning:** How should breaking changes to event payloads be handled? Schema registry needed?
4. **Dead Letter Queue:** What happens when an event consumer fails? Retry policy? Dead letter queue?
5. **Event Ordering:** Are there events that must be processed in order? (e.g., appointment.created before appointment.confirmed)
